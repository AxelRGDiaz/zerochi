# Decisions

| ADR | Decision | Consequence |
|---|---|---|
| 001 | Tauri 2, not Electron | Smaller native utility; Rust toolchain required. |
| 002 | No backend in V1 | State and polling remain local. |
| 003 | Gmail API, not IMAP | Official OAuth/history model. |
| 004 | Gmail read-only | No Gmail mutation; scope review remains a launch risk. |
| 005 | Pending differs from unread | Initial historical unread does not inflate Zerochi. |
| 006 | Opening from Zerochi consumes locally | Idempotent `openedFromZerochiAt`; Gmail unchanged. |
| 007 | Provider-independent PetEngine | Only normalized snapshots enter pet logic. |
| 008 | Declarative PNG sprite sheets | Variable rows/frames/FPS/loop without component hardcoding. |
| 009 | Hidden UI stops animation | No continuous visual timer while popup is closed. |
| 010 | Secrets stay outside frontend | Rust secure-store port; no tokens in React or plaintext. |
| 011 | One modular desktop process | Avoid backend, DI framework, event bus, and heavy database. |
| 012 | Worktrees per specialist wave | Ownership branches reduce collisions; Lead integrates. |
| 013 | M0 bundles macOS `.app` only | DMG/signing/notarization stay in M17; native code still receives a full bundle check. |
| 014 | Native macOS Keychain is the V1 secure store | Rust uses `keyring-core` + `apple-native-keyring-store`; Protected Data for signed builds, legacy adapter only for unsigned development; Stronghold is unnecessary in V1. |
| 015 | Google app configuration is Rust-only and build-injected for distribution | Debug may read the Desktop credential pair from an ignored local `.env`; production injects both at compile time through the protected wrapper. Neither may cross into React/logs or a bundled plaintext file. Decision 030 supersedes the original client-ID-only debug restriction. |
| 016 | Herdr topology is repository-defined and idempotent | `.agent/herdr-agents.json` defines six globally named agents; a safe bootstrap creates one main workspace plus five isolated short-lived worktrees and only performs onboarding. |
| 017 | `add_account` is a zero-argument Rust-owned OAuth command | UI receives only a normalized `MailAccount` or a sanitized tagged error; OAuth configuration and secrets never cross into React. V1 serializes add attempts. |
| 018 | OAuth commit and Gmail baseline have distinct failure semantics | Once secret and account are durable, the UI result/snapshot returns without awaiting baseline; the scheduler retries cursor-less accounts and historical mail never becomes pending. |
| 019 | The native tray is a projection of normalized account count and pending total | No-account sleep and pet mood thresholds remain consistent without exposing provider or OAuth state to the tray. |
| 020 | Account and observed-message state share one versioned atomic document | Cursor, pending, and new metadata cannot diverge across a crash; v1 migrates to v2 with no historical pending. |
| 021 | Sync health crosses to UI as a sanitized per-account tagged event | The local account UUID is sufficient correlation; provider errors and identity fields remain Rust-only. |
| 022 | Native OAuth completion restores and publishes before background Gmail work | Popup visibility and durable account feedback cannot depend on baseline/network success; the original OAuth result remains authoritative. |
| 023 | Token-exchange diagnostics reuse the M4 tagged-error contract | Allowlisted client/scope configuration failures map to `config_invalid`; `invalid_grant` remains a retryable `token_exchange_failed`. Provider bodies and descriptions are discarded, preserving actionable UI without expanding or leaking through the command DTO. |
| 024 | Local OAuth troubleshooting uses compile-time debug-only categories | A closed enum may emit one static token-exchange category to stderr in debug builds, including official configuration failures such as redirect mismatch, invalid request, and unsupported grant type. Release binaries contain no diagnostic emission and arbitrary provider text can never reach the sink. |
| 025 | `invalid_request` detail is normalized before diagnostics | Debug troubleshooting may inspect the ephemeral provider description only to match fixed OAuth parameter names and immediately collapse it to a static category. Raw descriptions and values remain forbidden in output, state, errors, fixtures, and release code paths. |
| 026 | Google Desktop client credential is an extractable build credential, not a secret boundary | The real token endpoint requires it for the configured Desktop client. Zerochi embeds it only in the native build, retains PKCE/state as the authorization defense, stores user refresh tokens separately in Keychain, and requires rebuild/redistribution for credential rotation. |
| 027 | Build injection must not leak raw credentials through Cargo metadata | Release `build.rs` reads protected CI variables, validates them, and generates masked byte arrays without `env!`, value-bearing Cargo directives, or raw sidecars. CI builds from a clean target, scans textual artifacts, uploads only the signed app/package, and treats masking solely as metadata hygiene—not confidentiality. |
| 028 | Gmail unread and Zerochi pending are separate counters | Superseded in provider mechanics by Decision 036. Gmail unread drives badges/ambient presentation; locally observed unopened messages drive feeding/events and pending. Neither counter overwrites the other. |
| 029 | Account removal is local-first with bounded best-effort provider revocation | Keychain deletion and atomic local-state removal are required for success; Google revocation is attempted without allowing an offline provider to retain an unusable local account. Per-account isolation and race guards prevent poll resurrection. |
| 030 | Debug OAuth configuration uses `dotenvy` for the complete Desktop credential pair | Process variables take precedence; otherwise Rust may read both values from an ignored local `.env`. Release builds never load dotenv and retain the clean-target protected build injection and artifact scan. |
| 031 | Visible totals and ambient pet presentation share one Gmail unread source | The popup global count, every account badge, menu-bar number, ambient face, and idle phrase derive from the saturating sum of active `inboxUnreadCount` values. Zerochi pending remains separate for local mail/feeding transitions. Faces/copy use ranges 0, 1–5, 6–15, 16–30, 31–50, and 51+; copy variation is deterministic and testable. |
| 032 | The main window behaves as an anchored menu-bar bubble | Tauri removes native decorations and provides a transparent initially hidden canvas; React draws an original rounded shell, shadow, and comic pointer; a tray click hides the visible bubble or positions and opens the hidden bubble beneath the real icon. Accessibility headings and hide-on-blur remain intact. |
| 033 | New-mail notifications originate only from newly inserted messages after the atomic incremental commit | The sync outcome carries the exact deduplicated committed records to a best-effort native adapter. Baselines, recovery, hydration, Gmail unread changes, and failed/duplicate commits stay silent. The native hierarchy is persisted account email / normalized subject / normalized sender with bounded fixed fallbacks and the bundled `notification-chime`. Its original UUID-only account-activation clause is superseded by Decision 037. |
| 034 | Local release packaging may consume the ignored root dotenv through the protected wrapper | A complete process/CI credential pair has priority. When neither variable exists in the process, the wrapper may load one complete pair from the bounded regular root `.env`; partial process state fails instead of mixing sources. Runtime release code still never reads dotenv, and artifact scanning/fresh-target rules remain mandatory. |
| 035 | Gmail unread commits independently and the central scheduler owns all polling | A valid INBOX unread observation remains useful even if later history/metadata work fails, so it is persisted and published separately without advancing cursor or creating pending mail. Healthy polls run 30 seconds after completion, due accounts run concurrently under per-account guards, and add/remove wake the scheduler rather than spawning duplicate work. |
| 036 | Gmail INBOX unread is an authoritative persisted id set | OAuth requests only `gmail.readonly`; `users.getProfile` supplies identity/cursor. Baseline, recovery, and every successful poll paginate `messages.list(labelIds=INBOX,q=is:unread)` as final membership, while History supplies only new-message candidates and the next cursor. One atomic CAS commit prevents counter/cursor drift; no `labels.get` poll or backend is required. |
| 036 | User-triggered mail checks advance central scheduler eligibility rather than invoking Gmail directly | `open_account` requests an immediate poll for its one account without delaying browser navigation; zero-argument `check_mail_now` does the same for all active accounts and acknowledges only enqueue. Its Rust unit result is represented as `null` by Tauri and normalized by UI. Repeated manual intent during an in-flight poll coalesces into one trailing immediate poll under the existing guard; acknowledgement is bounded to five seconds, fast success keeps pending feedback visible for 800 ms, feedback resets on leaving Settings, and actual results retain the normal snapshot/status/notification semantics. |
| 037 | Native notification activation opens a Gmail conversation best-effort with account fallback | The native identifier remains an opaque digest while a bounded process-local Rust map retains `accountId + messageId`. Activation revalidates durable account/message state, resolves `threadId` internally, and attempts an allowlisted Gmail Web conversation deep link; native rejection falls back once to the account. Expired, prior-process, removed, or mismatched targets are no-ops. Browser tab inspection and automation are rejected for privacy, permissions, portability, and reliability. |
| 038 | Dock suppression is enforced before and during runtime | The bundle declares `LSUIElement=true` to prevent LaunchServices from creating a transient Dock tile before Tauri's Ready callback. Runtime setup and window restoration retain `Accessory` policy and explicitly disable Dock visibility as defense in depth. |
| 039 | Unread state is reconciled locally without a backend | Every successful account poll obtains an authoritative paginated `INBOX + UNREAD` set, combines it atomically with the History cursor and eligible new-message metadata, and publishes the durable snapshot. React consumes native snapshots and recovers transient listener registration with bounded retries; it never polls Gmail directly. |
